This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Who's building this

SuperCapybara is a web game made by Ethan (age 9), who writes the prompts and owns the creative vision, with support from his dad. Talk to Ethan in short, simple, friendly language. Ask him about the creative choices (characters, worlds, enemies, powers). Make the technical choices yourself. Keep changes small and playable so he can try each step.

## Game vision

- World 1: side-scroller (city). World 2: 3D (space). World 3: side-scroller (volcano). All three are built.
- Cube Islands: a secret 3D "Pokémon Quest" world, reached through a portal in World 1.
- Beating a boss gives a key that unlocks travel to other worlds.
- Full design (players, power-ups, bad guys, bosses, ⚡ money) is in `GAME_DESIGN.md`. Ethan's original drawings are in `concept-art/`. Look at them before drawing a character, and keep `GAME_DESIGN.md` updated as he decides things.

## Commands

- `npm run dev`: start the dev server (Vite) at http://localhost:5173
- `npm run dev:ipad`: same, but also reachable from other devices on the home Wi-Fi (for testing on iPad/iPhone; open `http://<this Mac's IP>:5173`)
- `npm run build`: production build to `dist/` (for the `/SupaCapybara/` path; `npm run preview` serves it at http://localhost:4173/SupaCapybara/)
- **Hosting:** every push to `main` builds and publishes the game to GitHub Pages (https://herrshabi.github.io/SupaCapybara/) via `.github/workflows/deploy.yml`. The repo's remote is `git@github.com:HerrShabi/SupaCapybara.git` (SSH). Only commit or push when Ethan's dad asks.

- **Offline / install to the home screen (PWA):** `public/manifest.webmanifest` and the app icons in `public/icons/` (the only image files; they were made by drawing SuperCapybara with the game's own code). The build's `offline()` plugin in `vite.config.js` writes `dist/sw.js`, a service worker that caches every built file under a versioned cache name (new build = new cache, old ones deleted). `src/main.js` registers it only in production, checks for a new version whenever the app comes back to the front, and reloads once when a new version takes over (so installed apps update right away). Test offline with `npm run build`, `npx vite preview`, load the page, stop the preview server, and reload. The home-screen app keeps its own save (localStorage), separate from the browser's.

There are no unit tests or linter. To check that something works in the real game, run `node scripts/playtest.mjs '<steps>'` while the dev server is running (or set `PLAYTEST_URL` to test another address, like the built site). It drives headless Chrome with real key presses, saves screenshots, and can reach into the scene through `window.game` (that's only set in dev mode, in `src/main.js`). See the top of the script for the step format. Look at the screenshots before saying something works. The test browser uses software WebGL, so Phaser runs in WebGL and World 2's 3D works. If WebGL suddenly fails, leftover headless Chrome processes are the usual cause (the script now kills its browser on exit). The screenshots are 960x453 page pixels, which is what `touchdown` uses.

## Architecture

- Phaser 3 with Arcade physics, bundled with Vite, in plain JavaScript (ES modules). Entry point: `src/main.js` (game config, scene list).
- The game starts on `AccountsScene` (WHO'S PLAYING?: up to 4 players, each with a name, a hero picture and their own save; the accounts live in `save.js` (`loadAccounts`, `addAccount`...), and `loadSave`/`writeSave` always use the current player's save; the title's 👤 button comes back here), then `TitleScene` (modes: STORY → `MenuScene`, ADVENTURE → `AdventureScene`, TRAINING → `TrainingScene`, 2 PLAYERS → `TwoPlayerScene` → a world in team mode or `BattleScene`; plus 🎬 credits and reset). `MenuScene` is STORY's menu (character select): a slim top bar, a centered row of hero cards (◀ ▶, buying locked heroes), a card per world with its picture and name (`WORLD_LOOKS`, ▲ ▼; 🥊 Boss Rush next to the WORLDS title), the difficulty and one wide PLAY button on the left, and the SHOP button (opens the supermarket) with the keys under it on the right. Its layout constants (`LEFT`, `LEFT_WIDTH`, `RIGHT`, `RIGHT_WIDTH`, `CARDS_TOP`) are at the top of the file. The level scenes go back to it on a win or ESC.
- `src/characters.js` is the data for every hero (`attack`, `doubleJump`, `invisibility`, `fireAura`, `price`, `unlockKey`), plus the power-up list and the boss keys. `src/save.js` keeps the save (bolts, keys, owned heroes, power-ups, selected hero) in localStorage. Every scene loads it fresh with `loadSave()` and writes it with `writeSave()`.
- `src/Player.js` is the hero you control: movement, jumping, every hero power (including Bloodmoon Cat's homing moon and shadow form) and the power-ups (Shield, Fly, Mecha), all driven by the character data and `save.powerUps`. The level asks `player.unhurtable` (shadow or Mecha) before hurting, and implements `nearestTarget(x, y)` for homing shots. It doesn't know about bad guys: attacks call back into the scene through `scene.hitArea(rect, damage)`, and the scene sets up overlaps for `player.lasers`. When any attack lands, the scene calls `player.landedHit()`.
- One scene per world in `src/scenes/`. In `World1Scene.js`, the whole level layout is data arrays at the top (ground, platforms, bolts, bad guys). Edit those to change the level. World 1 ends in a locked boss room (the last screen, starting at `ARENA_START`). Walking in starts the Pizza Boss fight: a helicopter drops him in, and the checkpoint moves to the room's door. Picking up the key the boss drops wins the level and saves the `world1` key.
- **Every word the player sees goes through `t('key')` from `src/i18n.js`**, which has English and German (Ethan's friends only speak German). When you add text, add the key in both languages. Hero names stay the same in both. Scenes call `setLanguage(save.language)` in `create()`.
- Difficulty (`src/difficulty.js`, picked in the menu and saved as `save.difficulty`) controls hearts, how bad guys shoot, and boss strength. A level reads it as `this.settings`. Don't hard-code those numbers in a scene.
- **Side-scrolling worlds (1 and 3) share `SideScrollerScene`**: hero, bolts, bad guys, getting hurt, the boss bar, the key, winning. Each world passes its layout to `super()` and fills in `createScenery`, `groundAt`, `createBoss`, `bossEntrance`, `bossAction`, `updateBoss` and `afterWin` (see the comment at the top of that file). Put new shared behavior there, not in a world.
- Boss Rush runs World1, then `GrapeMoonScene` (Grape Boss in 2D on a moon, low gravity, Boss Rush only; he pops into a juice splash and goes straight to `win()`), then World3, with `scene.start(key, { bossRush: true, hearts })`. Each side-scroller then starts at its arena, and `level.bossRushNext` decides what comes next. `EndingScene` (the YOU WIN credits) plays after the first win of World 8, the last world (`afterWorld` in `src/trips/worlds.js`); the secrets still unlock with the `world3` key, and World 3 goes straight on to the balloon trip.
- Secrets unlock with the `world3` key: heroes with `secret: true` show up in the menu (owned for free), and so do the Boss Rush button and secret colors. Hero textures for a palette are keyed `heroKey(id, palette)` (e.g. `supa-cat~2-idle`). Always go through `heroKey` and `createHeroTextures(scene, palette)`.
- World 3 (`World3Scene`) is the volcano: lava pits (`fallY`), falling rocks (`this.hazards`), fire bad guys (`level.fire`), horned knights with TNT bolts (`level.knights`, handled in `SideScrollerScene`), and the Lava Dragon. The dragon has no gravity; tweens move it, and `this.busy` stops attacks from overlapping.
- World 1 is a city. `BUILDINGS` are solid (the gaps between them are a fall). Billboards and water towers are one-way platforms (`this.platforms`, which you can jump up through). Pizza Boss collides only with buildings, so the platforms never block him. The sky changes with the player's progress toward `ARENA_START`: day, then sunset, then night.
- Sound: `src/audio.js` makes every sound effect and song with the Web Audio API (there are no sound files). Use `audio.play('<effect>')`, `audio.playMusic('menu'|'city'|'boss')` and `audio.startCity()`/`stopCity()`. Songs are note strings in `SONGS`. Sound can only start after the first click or key press. The playtest tool's key presses count, so `audio.context.state` is `'running'` in tests. In dev, `window.audio` is exposed.
- **ADVENTURE is 3D too** (`src/adventure/`): `AdventureScene` wraps `AdventureWorld` the same way `World2Scene` wraps `SpaceWorld`. Unlike World 2, up is always +Y: the ground is the `groundHeight(x, z)` height map, and buildings, rocks, trees, caves and the door are boxes in `this.solids` that the hero collides with and stands on. The layout is in `map.js`. Progress is saved in `save.adventure` (opened chests, super boss beaten). The super boss is a state machine in `updateBoss` (evil → transforming → giant). The hero code supports several players: `this.players` (and `this.player` = player 1), each with its own keys (`KEYS.solo/p1/p2`), optional `padIndex`, models and camera. Hero methods take the player (`updateHero(p)`, `attack(p)`, `hurt(pos, p)`, `isDown(p, action)`). With 2 players, `render()` splits the screen and running out of hearts knocks you out until the other player revives you. Adventure itself is always solo.
- **Cube Islands** (`src/quest/`): `QuestScene` wraps `QuestWorld`, which **extends `AdventureWorld`** to reuse the hero (moving, attacks, powers, hurt, camera) and overrides the hooks listed at the top of `AdventureWorld.js` (`build`, `groundAt`, `updateWorld`, `targets`...). The ground is 2x2 blocks (`blockHeight`), drawn as one InstancedMesh per island. Layout (islands, pads, food, robots, cages) is in `map.js`. Progress is `save.quest` (food counts, babies `{ animal, color, xp, team }`, dragonBeaten; old saves are upgraded in the constructor). Bad guy kinds are the `KINDS` table, baby powers the `BABY_POWERS` table. The team tent and food shop are HTML menus (`menu.js`): opening one sets `this.paused`, and `updatePaused()` reads the keys. The portal is in `World1Scene` (`PORTAL`), and the way back is the `homePortal` at base camp (`createHomePortal`, exits with `'World1', { fromPortal: true }`, which starts World 1 next to the portal via the side-scroller's `data.start`); in 2 PLAYERS TEAM it starts Quest with `{ team }`, which makes it split screen (player 2 can be a baby: `setPlayer2`). `save.quest` helpers (`questProgress`, `addBaby`) are in `save.js`, because World 2's spaceship gives alien babies too.
- Win dances: `DANCES` and `pickDance(save, heroId)` in `characters.js`, bought in the supermarket and picked in the wardrobe (`save.dances`, `save.dancing`). 2D: `Player.dance(id)` returns how long it takes, and `SideScrollerScene.danceThen(done)` runs it before the key drops. 3D (World 2): `startDance`/`updateDance` in `SpaceWorld`.
- World 2 → World 3: after the key, `SpaceWorld.startTrip()` flies the rocket off (the grape SPLATs it) and exits with `onExit('World3')`, which starts World 3 with `{ crash: true }`. World 3 always starts with the crash landing (`startCrash`, not in Boss Rush or TEAM) using the side-scroller's `this.cutscene` hook (`updateCutscene`, `onEscape`); `save.crashSeen` lets ESC skip it.
- Baby Capybara's tips (`src/tips.js`): `save.tips` is the style ('excited'/'professor'/'baby') or null, `save.tipsSeen` the tips already shown; texts are `tip.<id>.<style>` in i18n. Side-scrollers: `level.tips` triggers plus `showTip(id, x, y)` in `SideScrollerScene`, which freezes physics, the running tweens, anims and the clock until JUMP/ATTACK. World 2: `checkTips`/`showTip` in `SpaceWorld`, which freezes by stopping `this.now` (`pausedFor`) and shows an HTML bubble. The title screen has the TIPS and FLYER (`save.titleHero`) buttons.
- STORY has 8 worlds: 1-3 are `World1/2/3Scene`, 4-8 are the story places, started with `{ world: n, heroes: [selected] }` (`WORLD_SCENES`, `startWorld` in `src/trips/worlds.js`). `StoryLevelScene.winWorld()` saves the `world<n>` key (all 8 are in `KEYS`). Then `afterWorld()` plays the trip to the next world (`TRIPS`; World 1→2 and 2→3 are the worlds' own rockets): trip scenes are in `src/trips/TripScenes.js`, built on `TripScene` (hero, controls, bolts, skip with `save.tripsSeen`, `arrive()`) and `RunnerTrip` (auto-run, jump, duck, floors/things/bolts from `this.course`) in `TripScene.js`. Trips can't be failed; they end in `startWorld(next)`. Note: macOS file names are case-insensitive, so don't make two files that differ only in case.
- **THE BAD GUY KING** story mode (`src/story/`): `story.js` has the `PLACES` and `save.story` (`saved` heroes, `freed` places, `lastPlace`). `StoryMapScene` plays `StoryIntroScene` (the King's opening movie, `story.introSeen`) the first time, then wraps `StoryMapWorld`, which **extends `AdventureWorld`** (same island, no chests or guards) and adds the places' pads and the pick-2-heroes menu (`QuestMenu`); its `exit(next, data)` starts a place's scene with `{ heroes }`. Each place is a side-scroller extending `StoryLevelScene` (which extends `SideScrollerScene`): it handles Q switching heroes via `Player.setCharacter`, the friend's trophy (`createTrophy`), the mini boss as a tinted robot copy (`createCopy`, `beamDownCopy`, `animateCopy`), and replaces `dropKey`/`win` with the trophy breaking and `freeFriend`. Places: `StoryCloudScene`, `StoryUnderwaterScene` (swimming in `DEEP` x ranges by changing body gravity, an air bar, jellyfish, ink splats on the screen), `StoryJungleScene` (swinging vines: the scene sets `player.held` so `Player.update` skips movement and moves the hero itself, then keeps the let-go flight going in `launches`; snake vines; coconuts hit back via `hitArea`; the quiz statue uses `freezeWorld`/`unfreezeWorld` from `SideScrollerScene`). The finale: the `castle` place (opens when `allFriendsFree`, takes every saved hero) starts `StoryCastleScene` (axes, shield croc knights blocked in `defeat`, then the 3-copy rematch in its arena: `defeatBoss` swaps to the next copy), then `StoryKingScene` (2 phases; the trophy zapper removes heroes from `this.heroes`; all gone = `scene.restart`), then `StoryEndingScene`. `story.kingBeaten` unlocks the `champion` hat, the title's King trophy and KING RUSH (`StoryCastle` with `{ rush: true }`: `bossRush` + `difficulty: 'extreme'`, `level.rushTitleKey`). Gold trophies use `goldify`/`ungoldify` in `art/gold.js`. A level can add its own bad guys to `this.badGuys` with data `bob`, `faces` and `shoot(badGuy, dir)`. `this.extraTouchButtons` adds touch buttons; comic bubbles come from `comicBubble.js`.
- **The Drawings World** (`DrawingsScene`, the door on the title screen): a side-scroller where everything is pen-and-pencil art from `src/art/doodle.js` (`pen()` wobbly lines, `pencil()` fills; doodle heroes shaped like Ethan's clay models via the side-scroller's `heroLook(id)` hook, and drawn hats via `this.hatStyle` (`{ prefix, anchor }`, passed to `Player`); doodle bad guys swap textures after `super.create`). Two bosses: `this.boss` (Pizza) and `this.grape` with their own hp (`damageDuo`), merging into the monster (`merge()`, then normal `hitBoss`). Winning sets `save.magicPencil`.
- **Drawing mode** (`src/sketch.js`, `save.drawingMode`, the ✏️ switch in the STORY menu): the `SketchFX` post effect (registered in `main.js`) on the side-scrollers' and trips' main camera, plus a second clean camera (copying the main camera's scroll in its `preRender`) for the HUD (objects with scrollFactor 0 and depth ≥ 9) and for whatever the scene's `isCleanObject(child)` says (the drawn heroes and hats, so they aren't outlined twice); drawn heroes and hats via `useDrawnHeroes`. World 2 renders through `ThreeSketch` (`SpaceWorld.draw()`). The Drawings World sets `drawnWorld` so it's left alone.
- **The magic pencil** (`src/magicPencil.js`, action `pencil` = E / ✏️ / right stick): in `SideScrollerScene` when `save.magicPencil`; it freezes the world, you pick a drawing (`PENCIL_DRAWINGS` in `art/doodle.js`: bomb, bridge, rocket, tornado) and trace its dots (pointer, or hold jump/attack). The bomb calls `blastAt(x, y, radius, damage)` (a level can extend it, like the Drawings World for Grape Boss); the bridge adds a timed zone to `this.platforms`; the rocket is kept going in `afterPlayers()`; the tornado is a tween that defeats bad guys it passes.
- **The secret capybara disco** (the easter egg in every STORY world, `src/disco.js`): an HTML party overlay (`showDisco`). Side-scrollers set `level.disco: { x, y, prop?, ground? }`; `SideScrollerScene` draws the prop (`art/discoSpots.js`) and the crack, which any attack breaks (`hitArea`, lasers, `blastAt`), then freezes the world (`this.disco`) during the party. World 2's crack is on the back of the parked rocket (`createDiscoCrack`/`openDisco` in `SpaceWorld`, with pictures from `World2Scene`).
- **The magic strawberry** (`src/strawberry.js`): every disco party gives one (`discoReward`: golden the first time per world, `save.discosFound`), kept in `save.strawberries` (up to 3). Eating one (action `strawberry` = B / START / 🍓) starts a `Magic` (timer plus the `strawberry` song, `strawberryHurry` near the end): rainbow, `MAGIC_SPEED`, unhurtable, smashes on touch. 2D: `Player` (`rainbow`, option `strawberry`, off in TEAM and Battle); World 2: `SpaceWorld.rainbow`; ADVENTURE / Cube Islands: `active('rainbow', p)` in `AdventureWorld`.
- **World 1's portal keypad** (`src/keypad.js`, Ethan's drawing `concept-art/portal-keypad.jpeg`): the portal is closed until you walk up to the keypad (`KEYPAD`) and type `PORTAL_CODE` (8725, on the note stuck to it); `World1Scene.update` hands the frame to `this.keypad` while it's open (world frozen), and `openPortal()` swirls it open. Coming back from Cube Islands it's already open.
- COPYBARA (`copybara`, attack `'cuffs'`): hero looks can set `badge: true` (gold badge instead of the bolt) and `noCape: true` in `art/heroes.js`, `world2/models.js` and `art/doodle.js`. Handcuff shots carry `cuffs` data; `SideScrollerScene.defeat(badGuy, { arrest })` plays `arrest()` (jail bars, POOF), and World 2 calls `sendToJail`.
- AGENT WHISKERS (`agent-whiskers`, attack `'gadget'`, `grapple`, `hidden`): a cat drawn with `agent: true` (`drawCat` in `art/cat.js`, plus `world2/models.js` and `art/doodle.js`: suit, pink tie, sunglasses, no cape). Gadgets land, blink, and blast with `hitArea` (2D `Player.throwGadget`) or `landGadget` (World 2, Adventure); her double jump draws `grappleFlick`. She isn't bought: her cardboard box sits on World 2's `hideout` planet (`agentBox` in `level.js`, a ring from p3); `SpaceWorld.findAgent` adds her to `save.owned` and the box never comes back.
- **CAPTAIN WADDLE** (`captain-waddle`, a penguin with an orange cape; `jailed: true`, not bought): he sits in the jail cell of the police station on World 1's first roof (`STATION`/`CELL`/`LOCK` in `World1Scene`). Walk up and press X (or ↑): `tryKeys` freezes the world and tries the boss keys you own one by one (the last one fits; none = a "you need a boss key" bubble), he hops out, says his line, Copybara says sorry, and he goes into `save.owned`. Attack `'snowball'` (2D `Player.throwSnowball`, World 2 / Adventure shots with `makeSnowball`), `doubleJump`, and `slide: true` = C is the WADDLE SLIDE: 2D `Player.startSlide`/`updateSlide` (fast belly slide, `slide` frame from `art/penguin.js`, unhurtable, smashes on touch, `hitArea` every 150 ms); a simpler version in World 2 (`SpaceWorld.updateSlide`) and Adventure / Cube Islands (`AdventureWorld.startSlide`/`updateSlide`, tilts the model). The menu card shows "Free him in the city!" until he's freed.
- Hats: `src/art/hats.js` (2D textures and where each animal's head is) and `makeHat3D` in `world2/models.js`. Players get `hat` from `save.wearing[heroId]`.
- **World 2 is 3D with Three.js, not Phaser** (`src/world2/`). `World2Scene` is a thin Phaser scene that hides Phaser's canvas and runs `SpaceWorld` (its own renderer, loop, keyboard listeners and HTML HUD in `hud.js`) until you exit back to the Menu. In dev it's exposed as `window.world2`. Each planet pulls toward its own center: the player's "up" is away from the nearest planet's center, so you can walk around planets. Shots travel around the planet they started on (great circles), so they hug the ground. The layout (planets, jump rings, crystals, bolts, bad guys) is data in `level.js`. Models in `models.js` are built from simple shapes. Aliens: flying saucers are bad guys of kind `'saucer'` (with `hp` and `hitRadius`); their tractor beam (`this.beam`) can pull you into the spaceship, a separate floor planet (`SHIP` in `level.js`, `inShip`).
- Game controllers: the 2D levels (World1, World3, Training, Battle) read them in `controls.js`. Everywhere else (menus, 3D worlds), `src/gamepadKeys.js` turns controller buttons into the same fake key presses the touch buttons use. If you add a 2D scene that uses `Controls`, add its key to `READS_GAMEPAD` in `main.js`; a scene that reads controllers itself can also set `this.readsGamepad = true` (2-player Quest does).
- Input goes through `src/controls.js`: a `Controls` per player maps actions (left, jump, attack, special...) to keys for a scheme (`solo`, `p1`, `p2`) plus a game controller. Use `justPressed`/`isDown` with action names, never raw keys, in hero code.
- Two players: `SideScrollerScene` has `this.players` (and `this.player` = player 1). Anything touching "the player" must loop over `this.players` or use `nearestPlayer(x)`. Hearts are shared in TEAM. `BattleScene` is its own scene; it implements the same `hitArea`/`nearestTarget` hooks Player calls, with the attacker passed in.
- Menus need a tappable way back (no ESC on iPad): use `addBackButton` from `src/backButton.js`.
- Touch controls (`src/touch.js`) are HTML buttons over the game that send fake keyboard events (Phaser needs `keyCode`, Three needs `code`). So levels only listen for keys. Turn them on with `save.touch`. The left thumb is a floating joystick (`addJoystick`: it appears where the thumb lands and holds the arrow keys for the directions pushed, up/down only if the level uses them); 2 PLAYERS has one joystick per side. Test it with the playtest steps `touchdown`, `touchmove`, `touchup`.
- **The supermarket** (`SupermarketScene`, the SHOP button in the STORY menu) is the shop: walk along the shelves, X puts things in the cart, the rainbow cat at the checkout scans them and you pay. What it sells (power-ups, `SHOP_HATS` from `art/hats.js`, dances) is in `src/shopItems.js`; the wardrobe only picks hats and dances now.
- **Power-up switches** (`PowerUpsScene`, the POWER-UPS button or P in the STORY menu): every owned power-up (plus MEGA BEAM while you have some) gets an ON/OFF switch, kept in `save.powerUpsOff`. `save.powerUps` stays the full owned list (the shop checks it), but gameplay must read `activePowerUps(save)` / `isPowerUpOn(save, id)` from `save.js` (and `megaBeamOn(save)` for the MEGA BEAM); Multi Direction is off while the Shield is off. Buying a power-up switches it ON.
- **MEGA BEAM** (`src/megaBeam.js`, action `mega` = G / 🌈 / left stick): a used-up power-up counted in `save.megaBeams` (power-ups with `usedUp: true` in `POWER_UPS`). `Player` takes option `megaBeam`; the beam hits through `scene.hitArea` and the lasers go in `player.lasers`. World 2 has its own version, `SpaceMegaBeam` in `world2/spaceMegaBeam.js` (the beam bends around the planet, hits by angle so it reaches saucers, caps its damage to Grape Boss, and `active()` stops the saucers' tractor beams; its lasers are shots with `mega: true`). In the 3D worlds the controller's left stick press sends G, and B + Y sends Z (Freeze Ray), like `controls.js`.
- **SUPA SNIPER** (`src/supaSniper.js`, action `sniper` = T / 🎯 / A + Y): a power-up you keep (`'supa-sniper'`) plus used-up ammo (`'sniper-ammo'`, `save.sniperAmmo`, 5 per buy). Used-up shop items name their save counter in `stock` (with `pack` and `most`, see `shopItems.js`). In side-scrollers `this.sniper` freezes the world and draws a fake first-person "eyes view" of the bad guys ahead (scrollFactor 0, depth 40), then `defeat`s or `hitBoss`es what's under the target. World 2's `SpaceSniper` (`world2/spaceSniper.js`) moves the real camera into the hero's eyes (SpaceWorld's loop hands it the frame while `busy`) and raycasts, with planets blocking the shot.
- Rewards for beating bad guys and bosses (`BAD_GUY_REWARD`, `BOSS_REWARD`) are in `difficulty.js`.
- There are no image files. Art is drawn with Phaser Graphics and turned into textures at runtime in `src/art/`. `heroes.js` builds every hero's frames (`<hero-id>-idle/run1/run2/jump`) and the `<hero-id>-run` animation, using the per-animal drawings and shared cape/bolt pieces in `heroParts.js`. `effects.js` builds attack and power effects.
